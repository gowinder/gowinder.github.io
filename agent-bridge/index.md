# 离开工位以后：我给 Mac 上的 agent 装了一个手机入口，以及为什么手机上说「可以，合并」不算数


上一篇写结果文件，讲的是协调方和执行方怎么交接。那套东西能跑，但有个前提我当时绕过去了：执行方在本机，人也得在本机。后来我把重活收回本机自己跑，这个前提就变成了每天的问题——活在 Mac 上，人经常不在 Mac 跟前。

我平时用 Claude Code 和 pi，都接自己的 magpie 网关，日常模型是 DeepSeek v4.1 Flash，编码和杂活都是它，设计审核另找一个强一点的模型看（gpt 6.1 sol，之前用 Opus 5.5，用了几年的账号被封了才换）。活以编码为主，也拿它们上网收集资料，最近还找工作、投简历。会话开多少看事情多少，闲时一两个，忙起来十个以上，每个管一摊事。agent 跑完一轮或者问了个只有我能答的问题，就停在那儿等着。我在工位上当然没事，问题是我总有不在的时候，出去遛个狗，那个会话就干等半小时。

远程桌面我试过，为回一句话开个桌面太重了。隧道之类的方案要在内网留个入口，不想留。官方倒是有个 Remote Control，后面会说为什么用不了。看了一圈，自己做了一个，Agent Bridge，11 月 10 号建仓，14 号发到 0.11.0。干的事情很窄：手机浏览器里能看到 Mac 上的 agent 会话，能回话，如此而已。

## 动手之前先验证了五轮

这次没直接写代码。11 月 9 号先写了份方案，花了几天做预验证，主要是怕几个想当然。有的话听起来理所当然，实测完全不是那么回事，这个项目后面最大的坑也确实不在写不出来，在想错了。

验证下来，中继这条路是通的，Cloudflare 的 Durable Object 能做 WebSocket 房间，Noise 有标准实现，端到端加密不用自己发明。Claude Desktop 的 Code 会话，桌面开着的时候能往里送话，每个会话进程都在 `/tmp/cc-socks/` 下面挂了个 socket，实测送进去的消息落在同一条记录的末尾，界面上看得见，也没把记录写分叉。ChatGPT 那边的 Codex 线程能走它自己的 IPC，不过只能发给桌面里已经打开的线程，没打开的发不了。

也有当场划掉的。Claude 的普通聊天在本机根本没有本地记录，我装的这个版本连聊天界面都没有，这条线就不要再想了。所以最后的结论只能写「部分通过」，范围就按这个划，通哪条做哪条。

## 架构没什么花样

Mac 上装个 daemon，加一个菜单栏的小应用。它只往外连，连到 Cloudflare 的中继上挂着，家里网络不开放任何入站的东西，不用端口映射也不用改防火墙，我比较在意这条，为了远程回个话在路由器上开个洞，我不干。

中继看不见内容。浏览器和 Mac 之间是 Noise 端到端加密的，它只管转发密文，顶多知道房间号、什么时候有流量、多大的包。配对也不搞账号那一套，本机生成一个一次性令牌，只有哈希传到中继，令牌本身放在链接的 # 后面，那部分浏览器本来就不会发给服务器。配对时手机和 Mac 上各出一个 6 位的码，对上了才算数，令牌用完就废，几分钟过期。

麻烦的是适配器，每个 agent 存会话、收消息的方式都不一样，只能一个个接。Claude Desktop 的 Code、Claude Code 的命令行、ChatGPT 的 Codex、Codex 命令行、Antigravity、DeepSeek Harness，后来还有 pi。接完还得如实标能力，读不全的就标 partial。这些 agent 没有哪个给过稳定的接口，硬说全支持是骗人，也骗自己。

## 功能都是用出来的

第一版只有镜像，把桌面上的会话搬到手机上，能看能回。够用了几天，然后就卡在批准上，手机上说「可以，合并」，它不认。这个问题值得单独一节，放在后面。

破局的是托管会话。往别人的会话里塞话，语义上就是转达，那就不塞了，让 Bridge 自己拉起一个 Claude Code 进程，输入口归它管。从网页新建的会话都是这种，工具调用要批准、agent 要提问，都走协议回到浏览器，手机上点同意或者拒绝，是真的生效。代价是这种会话在桌面应用里看不到，两边是两套。0.1.7 上线之后，我的使用习惯就慢慢全挪过来了。

剩下的改动回头看全是被小事追的。Bridge 重启会把它拉起的进程一起带死，跑了一半的那轮就没了，后来加了个常驻的守护进程专门持有这些子进程，Bridge 重启只断一下连接，回合照跑，回来把中间的输出补上。agent 半夜跑完我不知道，又加了推送。再后来 pi 也能托管了，它本来就是我用得最多的，网页上能换模型、能给子代理单独设模型和思考等级。

## 我最常用的反而是三个小功能

todo 是 0.11 才加的，加之前我没觉得缺，加完离不开了。用着用着会突然想起一件事，可能是个功能，可能是个 bug，当时手头这个对话正在跑，又不想为它新开一个对话、多拉一个分支出来，就先记在 todo 里，标一下是功能还是 bug。等这个对话跑完、空出来了，点一下那条，它就接到输入框里发过去了。东西存在 Bridge 自己的库里，不怕清浏览器缓存，换台机器就是另一个库，这点要注意。

侧边栏在手机上不明显，在桌面浏览器里是主力。左边那一列可以一直开着，结构树、历史都在，哪个会话在跑、哪个在等我回话、哪个有没看的新回复，一眼就知道。会话里那条信息栏也是，上下文用了多少、挂着哪些后台任务，摊开摆在那儿。比起在终端里滚来滚去翻 TUI，我现在更愿意开着网页看，信息是摊开的，不用记。

还有一个快速切换，顶栏一个按钮，在最近两个对话之间来回跳。听起来小，用起来停不下来，因为我发现自己同时深跟的对话其实只有两个，开十个是有的，但注意力就两个之间转。再多，维护不过来。说到底 agent 再能跑，最后排队等的是我，AI 时代瓶颈是人脑，这个没办法。

这些功能现在长在我的日常动线里。通勤路上、遛狗的时候、在沙发上看电视、晚上躺床上、甚至坐在马桶上——只要想起来某个会话该回了，掏出手机就能看、能回、能安排下一件。能这样用的前提是托管模式基本就是全功能：不是桌面版的只读镜像，是会话本身就在手机上完整地跑。

## 批准不了，这件事我想了很久

往桌面会话里送话只有 peer socket 这一条路，送进去的话会被包上一层：

```
<cross-session-message from="uds:/tmp/cc-socks/<pid>.sock" from-name="Agent Bridge · <设备名>">
你说的话
</cross-session-message>
```

收到话的 agent 分得清内容和人。改代码、查东西这种，它照做。但合并、发版、删东西这类事，它会回一句，这话是另一个会话转来的，不算我本人说的。我一开始觉得这是障碍，后来觉得它是对的。Bridge 要是把这层包拆了，把手机上的话伪装成我在桌面输入框里打的，那任何一段被转发的文字都能冒充我去批准一次上线。这个口子不能开，开了这个工具的安全模型就全塌了。

所以现在就三条土办法。要么最后一步我回电脑自己点；要么在桌面那个会话里提前说好，检查都过了的 PR 你自己合，手机上再说合并，算在提前给的授权里；要么让它把命令打出来，我复制到终端自己执行。都不优雅，但语义是干净的。真要手机上批，就开托管会话，那边没有这个问题。

官方的 Remote Control 我认真查过，它在官方应用里发的话确实算本人回合，没有这层包。查完发现三条对不上：它要 claude.ai 订阅登录，不认 API key 也不认第三方网关，我本机走 magpie 又没登录，跑起来直接报错；它不给本地程序留接口，Bridge 没办法把手机的输入递进去；还有它的记录存在 Anthropic 那边，我做这个东西的前提就是内容不出自己的机器和密文通道。功能是好功能，解的不是我这个问题。

还有条路实验过，`claude --resume -p`，拿会话 id 把话追加进去。它是真执行，连提交都给你做了，但执行的不是桌面里开着的那个进程，是新拉起来的一个。桌面那个不读磁盘上的记录，新说的话进不了它的脑子，而且两个进程同时写一个记录文件，写着写着就分叉了，后加的那些话成了没人认的孤儿。回执说成功了，实际状态对不上，这种比做不到还坏，停了，不做。

终端里直接跑的会话还有个小问题，它弹出选择题的时候，网页上是答不了的。试了几种送法，要么通道不理，要么写进去的地方根本不是输入队列，要么权限不够。只有当会话跑在 herdr 的面板里时有办法，那个面板能把真按键送进去，先看清光标指着哪个选项，再按方向键和回车，只敢做单选，多选不敢碰。没有 herdr 的时候，老实回终端答。

剩下的限制一次说完吧。网页只能新建托管会话，别的适配器都是附着在已经有的会话上。读取普遍不全，缺工具输出、缺附件、缺早期的对话，都有可能。Antigravity 的桌面版只能看不能发。协议里有些方法写了还没实现，网页拿新消息靠轮询，聊天页五秒刷一次，不实时。界面只有中文。记录文件落在磁盘上没加密，靠系统给的目录权限挡着。一个房间只能绑一台 Mac，大概就这些，想起来再补 CHANGELOG 里都有。

## 现在的状态

0.11.0，MIT 开源，GitHub 上 [gowinder/agent-bridge](https://github.com/gowinder/agent-bridge)，有 DMG 下载，网页端在 [agent-bridge.craftstead.app](https://agent-bridge.craftstead.app)。签名公证要配了苹果的证书才有，没配的版本第一次打开得去系统设置里手动放行，README 里写了，没什么好美化的。

我自己的用法换过三茬。一开始用 Claude 桌面版的会话，镜像看着是方便，但真到要提交代码、开 PR 的时候就卡住，批准不了事，最后一步总得回电脑。后来换成 Bridge 托管的 Claude Code，能跑完整流程了。现在主要用托管的 pi，功能比较全，也比较开放，模型、子代理、思考等级这些都能在网页上直接设。

还有一件说出来有点绕的事：Agent Bridge 后期的开发，大部分就是托管 pi 通过 Agent Bridge 自己开发的。我有灵感先丢进它自带的 todo 里记着，完成一个，手动安排下一个，人在哪儿都能推进。等 app 设置里那个「自动更新」开关做到开了就全自己来（检测到新版就自己下载装上，不用我点「检查更新」和「立即更新」），我基本可以脱离 Mac 主机用它——工具做到能脱离自己的开发机继续开发自己，这条线算是闭环了。

下一步不急着加新 agent。订阅推送欠着，做了轮询就能退，那是体验上最大的一块，pi 托管还有几个边角在磨，先磨完再说。

最后留个问题，也是我真想听听别人怎么想的：一个能从手机直达你开发机的工具，做到什么程度你才敢让它常开着。我的答案就是前面那些，只出不进，中继看不见明文，批准权不外借。哪条松了，我宁可不用它。
